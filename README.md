# Jujishou测试

零依赖的浏览器抽卡小游戏：纯静态 HTML / CSS / JS，没有构建步骤、没有 npm、没有框架。

线上地址：<https://jujishou.github.io/jujishou/>

## 两个卡池

站内有两套互相独立的卡池，保底进度分别计算，卡面只用 5 张自备立绘。

### 卡池一 · 夜瞳（限定）

| 档位 | 出率 | 卡面 |
| --- | --- | --- |
| **UR（大隐藏）** | 0.3% | 夜瞳 |
| SR | 5.1% | 蓝耳机 |
| R | 94.6% | 永远怀念 |

### 卡池二 · 方块（限定）

| 档位 | 出率 | 卡面 |
| --- | --- | --- |
| **UR（大隐藏）** | 0.3% | 方块白 |
| R | 99.7% | 橘座 |

> 卡池二没有 SR 卡，所以 SR 的概率直接并入 R，十连保底 SR 在这一池自动关闭。

## 保底规则

- **大隐藏硬保底**：同一卡池累计 120 抽必出 UR，出货后计数归零。
- **十连保底**：同一卡池连续 10 抽必出 SR 及以上（卡池二没有 SR，此规则不适用）。
- 两个卡池的保底各算各的，互不影响。

因为硬保底的存在，大隐藏的实际出率约 **0.97%**，高于标称的 0.3% —— 页面统计里显示的是实际滚出来的值。

## 大隐藏的遮罩

UR 卡在第一次获得之前，卡面显示成灰度 + `???`。首次抽到之后永久解锁真名与彩色立绘。

## 后台

页面底部有「后台」按钮，输入专属密钥即可进入控制台：

- **数据总览**：总抽数、UR / SR / R 出货数、综合出金率、记录条数（每秒自动刷新）
- **卡池明细**：各池抽数、保底进度、大隐藏持有数
- **存档管理**：导出存档 JSON、导入存档、重置本池保底、清空全部数据
- **密钥工具**：在线生成新密钥，并给出对应的 SHA-256
- **原始存档**：实时显示本机 localStorage 里的完整 JSON

密钥不以明文保存。`app.js` 里只有它的 SHA-256（常量 `ADMIN_HASH`），校验在浏览器里用 Web Crypto 完成，因此**必须通过 https 或 localhost 访问**才能进入后台。

### 换密钥

用后台的「生成新密钥」拿到明文和新哈希，把 `app.js` 顶部的 `ADMIN_HASH` 换成新哈希，提交推送即可，旧密钥随即失效。

### 这是纯前端后台

站点是静态页，没有服务器。所以后台只能读写**当前这台设备浏览器里**的存档，无法汇总其他访客的数据；密钥校验也在本地，翻源码的人可以绕过。它挡的是随手点进来的人，不是攻击者。若要真正的服务端后台（汇总所有玩家的抽卡数据、服务端发号），得额外接一个后端服务。

## 存档

进度存在 `localStorage` 的 `starfall-gacha-v2` 键下，刷新和关页面都不会丢。换设备或换浏览器需要清空浏览器数据后重开，或用后台的导入 / 导出搬运。

## 本地预览

```bash
cd gacha-site
python3 -m http.server 8080
# 打开 http://localhost:8080
```

直接双击 `index.html` 用 `file://` 打开也能玩，但 `file://` 下没有 Web Crypto，后台进不去。
