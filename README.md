# Jujishou测试

零依赖的浏览器抽卡小游戏：纯静态 HTML / CSS / JS，没有构建步骤、没有 npm、没有框架。

线上地址：**<https://jujishou.dpdns.org>**（账号系统、存档、后台都在这台上，HTTP 自动跳 HTTPS）

另有两条备用地址（纯静态、没有后端，账号功能自动跳过）：
<https://jujishou.github.io/jujishou/>、`http://120.220.76.234:8880/`

## 两个卡池

站内有两套互相独立的卡池，保底进度分别计算，卡面只用 6 张自备立绘，每张立绘只出现在一个卡池里。

### 卡池一 · 夜瞳（限定）

| 档位 | 出率 | 卡面 |
| --- | --- | --- |
| **UR（大隐藏）** | 0.3% | 夜瞳 |
| SR | 5.1% | 蓝耳机 |
| R | 94.6% | 永远怀念 |

### 卡池二 · 方块（限定）

| 档位 | 出率 | 卡面 |
| --- | --- | --- |
| **UR（大隐藏）** | 0.3% | 方块白 + 西装客（各占一半） |
| R | 99.7% | 橘座 |

> 卡池二的两个大隐藏都在 UR 档里平分概率，所以单张实际是 0.15%；
> 这一池没有 SR 卡，十连保底自动关闭，只吃 120 抽的大隐藏硬保底。

## 保底规则

- **大隐藏硬保底**：同一卡池累计 120 抽必出 UR，出货后计数归零。卡池二两个 UR 都算数，抽到任意一个就重置。
- **十连保底**：同一卡池连续 10 抽必出 SR 及以上（卡池二没有 SR，此规则自动关闭）。
- 两个卡池的保底各算各的，互不影响。

因为硬保底的存在，大隐藏的实际出率约 **0.99%**（实测卡池二 50 万抽：UR 0.989%、最大间隔 119 抽），
高于标称的 0.3% —— 页面统计里显示的是实际滚出来的值。

## 大隐藏的遮罩

UR 卡在第一次获得之前，卡面显示成灰度 + `???`。首次抽到之后永久解锁真名与彩色立绘。

## 抽到大隐藏时的出场演出

抽到 UR 的那一下不会直接把卡摆出来，而是走一段演出：

1. **先全屏放一段视频**（10 秒，1280×720，带原声）—— 仓库、聚光灯、黑手套举起一张卡
2. **再让卡片从爆光里冲出来** —— 白闪、震屏、放射光线、冲击波、七十颗火花，卡片带着光晕旋转着放大定格

几个实现上的取舍：

- 视频**不在首页加载**，只有真的抽到 UR 了才去取（`preload="none"` + 第一次抽到才设 `src`）。
  1.1 MB，平均要抽三百多次才见得到一次 UR，按需取不会拖慢任何人。
- 视频**原声保留**，跟着站点右下角的音效开关走：开关是开着的就出声，静音了视频也静音。
  抽卡本身就是点击触发的，所以不存在被浏览器自动播放策略拦下的问题；
  万一真被拦了，会退一步静音再试，仍不行就直接进卡片动画，不会卡在那儿。
- **点一下跳过**：视频阶段点一下进卡片，卡片阶段点一下收尾；`Esc` / 空格 / 回车也行。
- 视频**加载失败、格式不支持、迟迟不开始播**（2.5 秒没 `playing`）都会直接进卡片动画。
  视频最长放 16 秒，到点强制进下一段，防止某个浏览器卡死。
- 老安卓不一定认识 `aspect-ratio`，卡片的宽高写的都是绝对值；系统开了「减少动态效果」时动画自动收敛。

界面上的点击也有声音（都是 Web Audio 现场合成的，没有额外音频文件）：
抽卡按钮、切换卡池、开关音效、重置，都有各自的短音。

## 账号与内测密钥

站点在内测，**没有账号进不来**：打开页面会先看到一道门禁，要么用一次性密钥注册，要么登录已有账号。

- **一次性密钥**：由站长在后台生成，形如 `5HVJ-QKBA-VM3M`（Crockford Base32，去掉了容易看错的 `I/L/O/U`）。
  一枚密钥**只能注册一个账号**，用完即废；把密钥发给谁，就等于放谁进来。
- **账号**：用户名 2~32 字节（中文也可以，`_` `-` 和字母数字随意）＋ 密码至少 6 位。
  密码在服务端以 PBKDF2-SHA256（12 万轮 + 随机盐）存盘，**明文密码不落盘**。
- **只需输一次**：登录状态是一个签过名的 `guid` Cookie，有效期 **一年**。
  所以「输入过一次后就再也不用输入」——除非自己点退出或清掉浏览器数据。
- **换设备不用密钥**：密钥只在**第一次注册**时需要。已经注册过的号，在别的设备上直接用户名 + 密码登录，进度跟着账号走。

存档从这一刻起绑定账号（服务端路径 `<data>/saves/<uid>.json`），
`uid` 是用户名的 SHA-256 摘要前 16 字节 —— 用摘要当文件名，省掉了所有「中文用户名怎么当文件名」的麻烦。

> 账号系统上线前留下的匿名存档不会丢：注册时如果浏览器里还带着旧的 `gpid` Cookie，
> 服务端会把那份存档复制给新账号。实在没被领走的，也会以「(匿名存档)」的身份出现在后台账号列表里。

**GitHub Pages 上没有后端**，探测不到 `/api/me`，门禁会自己让开，页面退回纯本机 `localStorage` 玩法。

## 后台

页面底部有「后台」按钮，输入专属密钥即可进入控制台：

- **服务器状态**：在线玩家数、占用字节、总抽数、启动时长、服务器时间、监听端口（每 5 秒自动刷新）
- **测试密钥**：一键生成一次性密钥，列表里能看到每枚「可用 / 已用于谁」，可复制、可删除，还能一次复制走全部未用的
- **账号**：每个账号的用户名、注册时间、抽数、存档大小，可搜索、按抽数 / 名字 / 大小排序，可展开看该账号的原始 JSON，也可以连号带存档一起删掉
- **审计日志**：每一次请求的时间、IP、方法、路径、状态码，可按 2xx / 4xx / 5xx 过滤
- **重启网站**：硬重启，先把所有人（包括你自己）的连接全部掐断，再让整个服务端重新起来，约 2 秒后恢复
- **本机存档管理**：导出存档 JSON、导入存档、重置本池保底、清空全部数据
- **原始存档**：本机 `localStorage` 里的完整 JSON（收在折叠面板里，要用时再点开）


### 「重启网站」有什么用

网页文件是每次请求现读的，所以**换卡面、改文案本来就不需要重启**。
重启要解决的问题是：已经打开页面的人手里那份 `app.js` 是旧的。

服务端每次启动都会生成一个毫秒级的 `boot` 号，通过 `/api/health` 暴露；
前端每 15 秒比对一次，一旦发现变了就自己 `location.reload()`。
配合「`html`/`js`/`css` 一律 `no-cache`」的响应头，在线的人会在 15 秒内自动换到新版本，不用手动刷新。

站内有两套部署形态，前端会自动分辨：

| | 静态托管（GitHub Pages） | 服务端（自己的云服务器） |
| --- | --- | --- |
| 后台入口 | 探测不到 `/api/health`，按钮自动隐藏 | 显示，需服务端密钥 |
| 门禁 | 探测不到 `/api/me`，直接放行 | 必须有账号，凭一次性密钥注册 |
| 密钥校验 | —— | 服务端 PBKDF2(120000 轮)，前端改不动 |
| 存档 | 只在本机 `localStorage` | 服务端 `saves/<uid>.json`，跟着账号走，换设备自动认领 |
| 审计 | 无 | 有，落 `access.log` |

## 两种部署形态

仓库里现在有两套后端，前端完全共用：

| | Cloudflare Workers（**现在用的**） | C 版（云服务器） |
| --- | --- | --- |
| 地址 | <https://jujishou.dpdns.org> | `http://120.220.76.234:8880/` |
| 源码 | `cf/`（`wrangler.toml` + `schema.sql` + `src/worker.js`） | `server/`（`server.c` 等） |
| 存储 | D1 数据库 | 服务器上的 JSON 文件 |
| HTTPS | 有（Cloudflare 证书） | 没有 |
| 为什么换 | 机房只放行「过白」域名，`dpdns.org` 这种免费域名备不了案，域名在那边用不了 | —— |

细节见 [`cf/README.md`](cf/README.md)。C 版仍然留着、也还能跑，当备份用。

## 服务端

服务端是 [`server/`](server/) 里一份零依赖的 C 程序，交叉编译成静态二进制后部署，
详见 [server/README.md](server/README.md)。它会：

- 用 `<id>.<过期时间>.<HMAC-SHA256>` 签会话 Cookie，后台 Cookie 是 `HttpOnly` + `SameSite=Strict`，
  玩家 Cookie 是 `guid`（一年有效，`SameSite=Lax`）
- 管账号：用户名 + 密码注册 / 登录，密码 PBKDF2-SHA256(120000 轮) 加盐存盘；一次性密钥一枚只能用一次
- 密钥以 PBKDF2-SHA256 加随机盐存盘，前端只把「密钥的 SHA-256」发出去，明文永不出浏览器
- 拒绝畸形 JSON、路径穿越（含 `%2e%2e`、`..%2f` 等编码变体）、跨玩家读写存档
- 同一 IP 十分钟内失败 5 次即限速，并记录审计日志
- 后台可以硬重启整个网站，并让所有在线页面在 15 秒内自动刷新

### 换密钥

在服务器上执行：

```sh
printf '%s' '新明文密钥' | sha256sum | awk '{print $1}'   # 得到 cred
/opt/gacha/gachad initkey <刚才的 cred>
/opt/gacha/start.sh                                        # 重启
```

旧密钥立刻失效，不必改任何前端代码。

## 存档

服务端在线时，进度同时存在服务端与本机 `localStorage`（键 `starfall-gacha-v2`）：
本机为空时会自动认领服务端那份，所以**只要登录同一个账号，换设备也能接着抽**；本机已有进度则以本机为准。
纯静态托管时只存在 `localStorage`，换设备需要用后台的导入 / 导出搬运。

服务端上每个账号一份：`<data>/saves/<uid>.json`，`uid` 是用户名的 SHA-256 摘要前 16 字节。
未登录时读写存档一律 `401`，所以「没账号就没法玩」不只是前端挡了一下，服务端也不认。

## 本地预览

纯前端部分：

```bash
cd gacha-site
python3 -m http.server 8080
# 打开 http://localhost:8080
```

带服务端（后台可用）：

```bash
cd gacha-site/server && ./build.sh /tmp/gachad && cd ..
/tmp/gachad initkey "$(printf '%s' '你的密钥' | sha256sum | awk '{print $1}')"
GACHA_PORT=8080 GACHA_WWW="$PWD" GACHA_DATA=/tmp/gacha-data /tmp/gachad
```

前端用的是相对路径（`api/health`、`api/save`），所以挂在任何子路径下都能正常工作。
